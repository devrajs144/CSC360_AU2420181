Today's lecture moved away from the graphics fundamentals covered earlier and shifted toward SSH, version control access, and a comparison between static and interactive graphics.

The session opened with an explanation of SSH (Secure Shell) and how it compares to HTTPS. Both are protocols used to establish secure communication, but SSH is primarily used for secure remote access and command execution, while HTTPS is used for secure communication over the web. This distinction is useful to remember, especially since both protocols came up again later in the context of accessing Git repositories.

A significant part of the lecture focused on how SSH and HTTPS are each used to access Git repositories. HTTPS typically requires entering credentials such as a username and password or a personal access token whenever authentication is needed, whereas SSH relies on key-based authentication, allowing secure access without repeatedly entering credentials once it has been configured. This made the earlier explanation of public and private keys more meaningful. A public key is shared and used to verify identity, while a private key remains secure on the user's machine and must never be shared. Together, these two keys form a key pair that enables secure authentication without transmitting passwords. Understanding how these keys work together was one of the clearest takeaways from the lecture.

The lecture also introduced SSH KeyGen, a utility used to generate SSH key pairs, along with Microsoft PowerShell as an environment where SSH commands can be executed, particularly for Windows users. Seeing practical demonstrations in PowerShell helped connect the theoretical explanation of SSH to a real development workflow, making the concept much easier to understand.

Returning to graphics, the lecture compared static graphics and interactive graphics. Static graphics are images that remain unchanged after being displayed, whereas interactive graphics respond dynamically to user input or other events in real time. This comparison served as a bridge between the earlier discussion of system interaction through SSH and the broader objective of the course, where user interaction will become an important aspect of computer graphics applications.

The lecture concluded with a discussion on vector graphics and raster graphics. Vector graphics are represented mathematically using paths, lines, and curves, allowing them to be scaled without any loss of quality. In contrast, raster graphics consist of a grid of pixels and tend to lose clarity or become pixelated when enlarged. This topic connected naturally with the concepts introduced in the previous lecture, where lines and curves were identified as the fundamental geometric primitives used to construct graphical objects.

Overall, the lecture successfully combined practical software development concepts with graphical fundamentals. Understanding SSH authentication, key generation, and repository access provided valuable technical knowledge that will be useful throughout the course, while the comparison between static and interactive graphics and the distinction between vector and raster graphics strengthened the conceptual foundation established in earlier lectures. The strongest takeaway from today's session was recognizing how mathematical representations, secure development practices, and graphical systems all contribute to modern computer graphics workflows.
