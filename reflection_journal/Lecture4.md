**Lecture Date:** 18/07/2026

Lecture 4 was about actually creating a square in Java, and it was interesting to see how much mathematics there is under the hood of something that seems so simple on the screen. First, instead of thinking of shapes as complete drawings, I had to think of them as a series of calculations that need to be performed to create the shape. From there, we moved into positioning, particularly how placing the centre of the square at the centre of the canvas makes the result balanced and predictable. It started out as a minor detail, but I realized that it is a key point that influences all the other calculations in the process.

With the positioning logic sorted out, the next topic of the lecture was finding the coordinates of the four vertices of a square, given just the length of its sides. At this point, it became more mathematical, as it was necessary to calculate the positions of the vertices rather than estimate them by applying the appropriate formula. It took some mental effort to understand initially, but once it became clear, I could see why each vertex needed to be calculated relative to the centre point established earlier. This was followed by an investigation of the use of midpoints in drawing each side of the square, and how the position of each vertex is directly linked to the actual line-drawing process. The earlier lecture on lines and curves became more applicable during this part because it was evident how these foundational primitives are used in an actual construction.

Next, the mathematical side of the lecture was over and we switched to the Java implementation. We discussed how to set the outline colour of the square and how to fill the square with colour internally. This was helpful after performing the coordinate calculations because it brought the two sides of the lecture together: mathematics on one side and rendering logic on the other. It made the overall process feel much less disconnected.

The second half of the class was devoted to version control rather than graphics. We went over the structure of a typical Git repository and the use of `.env` files for storing sensitive configuration variables separately from the main code. This naturally led to a discussion of `.gitignore` files and why certain types of files should not be version-tracked. This seems obvious in hindsight, but it can be confusing when you are just starting out with Git.

Lastly, we walked through a sample Java program that combined all of the above to create and display a square on the screen. After going through the code with the theory already in mind, it was much easier to see the relationship between the mathematics and the actual implementation than it would have been by looking at either one separately.
