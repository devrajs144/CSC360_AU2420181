Today's class began a little differently, since we spent the first part reviewing markdown files written by classmates to see how others had approached the reflection journal assignment. Going through someone else's work and picking out what worked and what didn't was more useful than I expected, because it's easier to notice weak transitions or awkward phrasing in someone else's writing before recognizing the same habits in your own. This led into a broader discussion on the dos and don'ts of writing reflections, covering what should actually be included versus what tends to clutter the writing unnecessarily. Alongside this, we went over markdown formatting itself, how headings, spacing, and structure affect readability, and even touched on how to view markdown files locally without needing a full IDE open just to check formatting.

The lecture then shifted into graphics again, specifically the process of creating a frame and eventually drawing shapes inside it. Going over this again helped clarify something I had slightly mixed up earlier. The actual order is to first create the frame, which acts as the main window, and then create a panel, which is the surface where drawing and components actually get placed. Rather than the frame being put inside the panel, it's the reverse: the panel gets added into the frame, and once that structure exists, colors and shapes get applied within the panel itself, usually through overriding a paint method. Understanding this order makes more sense now, since the frame is essentially the container and the panel is what does the actual rendering work inside it.

We also covered classes, subclasses, and anonymous classes in Java, using an example involving a general class and a more specific subclass extending it, which reinforced the idea of inheritance building specialized behavior on top of a general structure. This connected well with the practical drawing exercises, where we worked through how to draw a rectangle using two points, and a triangle using three points, with two of the points chosen somewhat freely and the third requiring more careful placement to keep the shape sensible.

Later, we revisited the frame and button code from an earlier session, which helped reinforce syntax that keeps showing up throughout the course, import statements, public class declarations, naming conventions, JFrame usage, and how arguments get passed when drawing shapes. Seeing these pieces repeated across different examples is starting to make the overall structure feel more familiar rather than something I have to look up each time.
